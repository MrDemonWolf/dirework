Once you've connected a [bot account](/docs/twitch-oauth#step-5-connect-the-bot-account), viewers can interact with DireWork through Twitch chat commands.

<Callout type="info" title="New to the stream? (for viewers)">
  1. Type `!task` and what you're working on, like `!task read 10 pages`.
  2. Work along with the stream.
  3. Type `!done` when you finish.

  Stuck on a command? Type `!dw help` and its name, like `!dw help done`.
</Callout>

<Callout>
  **The bot listens while its page is open.** Copy the **Widget URL** from **Dashboard →
  Bot** into an OBS browser source or a Moblin widget (it's invisible on stream), or the
  **Dock URL** into an [OBS custom browser dock](/docs/twitch-oauth#where-to-keep-the-bot-page)
  or a pinned browser tab.
  While that page is open, the bot reads chat and replies — close it and the bot goes
  quiet. If you regenerate the bot token, re-copy the URL.
</Callout>

## Task commands (all viewers)

| Command | Description |
| --- | --- |
| `!task <text>` | Add a new task (your first task automatically becomes your active one) |
| `!done` | Mark your active task as done |
| `!done <number>` | Mark a specific task by position as done (`!done 2` and `!done #2` both work; anything that isn't a number gets a usage hint instead of completing your active task) |
| `!edit <number> <text>` | Edit a specific task by position |
| `!remove <number>` | Remove a specific task by position |
| `!focus <number>` | Set a task as your active/focused task |
| `!start <number>` | Start a waiting task beside your focus (up to 3 going at once; with nothing going it becomes your focus) |
| `!pause` | Pause your focus; your next started (or waiting) task takes over |
| `!pause <number>` | Pause a specific task you started (it goes back to waiting) |
| `!check` | Show your current active task, plus how many more you started |
| `!check @user` | Show another user's active task and their started count (the `@` is optional, and trailing punctuation like `@user?` is ignored) |
| `!today` | Show your active task, next two tasks (with their numbers), and how many more are queued |
| `!next <text>` | Complete your active task and start a new one |
| `!help` | Post the 3-step starter guide (the streamer can reword it) |

### Who can add tasks

**Dashboard → Bot → Live controls → Who can add tasks** limits the two commands that create
tasks, `!task` and `!next`. It saves the moment you pick a level:

| Level | Who can add tasks |
| --- | --- |
| **Everyone** (default) | Any viewer |
| **Followers** | Followers, subscribers, VIPs and mods |
| **Subscribers** | Subscribers (founders too), VIPs and mods |
| **VIPs and mods** | VIPs and mods |

- The streamer and mods can always add tasks. Every other command (`!done`, `!start`,
  `!check`, …) works for anyone who already has tasks.
- Subscribers and VIPs come from the badges Twitch sends with each chat line, read by the bot
  page the same way it reads mod badges.
- **Followers** asks Twitch once per viewer, as the bot account. A confirmed follow is
  remembered for 7 days and a "not following" for 10 minutes, so a viewer who just followed
  gets in soon. Subscribers, VIPs and mods skip the check.
- For **Followers**, the bot account must be a **mod** in your chat (`/mod YourBot`) and must
  have been connected with the follower permission. A bot connected before this setting
  existed needs one reconnect: Bot settings shows **Reconnect the bot to allow follower
  checks** when it does.
- If Twitch can't answer (a hiccup, the bot isn't a mod, or it hasn't been reconnected), the
  bot refuses the task rather than letting everyone in, and replies **Follow check failed**
  ("I couldn't check your follow just now…"). The viewer can try again a minute later.

## Task commands (broadcaster / mods)

| Command | Description |
| --- | --- |
| `!clear all` | Clear all tasks from the list |
| `!clear done` | Clear all completed tasks |
| `!clear @user` | Remove all tasks from a specific user (the bot says so when that user had none) |

## Timer commands (broadcaster / mods)

| Command | Description |
| --- | --- |
| `!timer start` | Start the timer with default settings |
| `!timer start <cycles>` | Start the timer with a specific cycle count |
| `!timer pause` | Pause the timer |
| `!timer resume` | Resume the timer |
| `!timer skip` | Skip the current phase |
| `!timer reset` | Reset the timer to idle |
| `!timer eta` | Show time remaining in the current phase and the whole session (while paused, the frozen time left) |

Task numbers are the ones `!today` shows, so `!edit #2 …`, `!remove #2`, `!focus #2`, `!start #2` and `!pause #2` work as well as the plain number.

When `!timer pause`, `resume` or `skip` can't do anything, the bot says why instead of
replying "Done.": pausing a paused timer gets `The timer is already paused. Use !timer resume
to continue.`, resuming a running one gets your **Timer Running** reply, and if another
action changed the timer at the same moment it replies `The timer changed just before that,
so I left it alone. Check it and try again.` These fixed replies aren't editable.

## Moderation commands (broadcaster / mods)

| Command | Description |
| --- | --- |
| `!mute` | Pause the bot: it ignores every command and posts nothing |
| `!unmute` | Resume the bot |
| `!block @user` | Block a viewer and remove every task they added |
| `!unblock @user` | Let a blocked viewer use commands again |

- **Muted means everything.** While muted the bot ignores every command, task, timer and
  meta commands included, and posts nothing in chat. The only command that works is a
  mod's `!unmute`. The board and timer stay as they are. You can also flip the **Mute bot**
  switch at the top of **Dashboard → Bot**.
- **Blocked viewers get no reply.** The bot silently ignores their commands, and blocking
  removes every task they added. `!unblock` restores their commands, not their tasks.
- **The streamer can't be blocked**, and the streamer's own commands always run.
- **Blocking is by Twitch login.** A viewer who renames their account slips the block;
  block the new name too. The block list holds up to 200 names and is also editable under
  **Moderation** on **Dashboard → Bot**.

### Bans and timeouts

- **A timeout keeps the viewer's tasks.** Nothing changes on the board.
- **A ban removes the viewer's tasks 5 minutes later**, so a mistaken ban can be undone
  first. If the viewer chats again within those 5 minutes they were unbanned, and their tasks
  stay. A second ban of the same viewer in that window doesn't add another removal.
- **The bot page must stay open** for those 5 minutes: it holds the timer. Close or reload
  it in that window and the removal is skipped; clear the viewer with `!clear @user`.
- **When the bot account is your own Twitch account**, DireWork also asks Twitch whether the
  ban still stands before removing anything (Twitch only answers that for the channel's own
  account). A separate bot account can't ask, so the removal goes ahead unless the viewer
  chatted again.

## Meta commands (always available)

These commands are always enabled regardless of task or timer command settings (but, like
everything else, they stay silent while the bot is muted).

| Command | Description |
| --- | --- |
| `!dw` or `!dw help` | Posts the built-in 3-step starter guide. It can't be reworded, so it still works if the streamer customized `!help`. If task commands are off, it says so instead |
| `!dw help <command>` | Explains one command in plain words with an example, like `!dw help task`. Takes `task`, `!task`, any capitalization, or one of the streamer's aliases; mod-only commands are marked "(mods only)". `!dw task` works too |
| `!dw commands` | Same as `!dwhelp` |
| `!dwhelp` | Posts a link to this commands reference page — or, if no docs URL is configured, an inline list of the available commands |
| `!dwcommands` | Same as `!dwhelp` |

## Active task and focus

When you add your first task with `!task`, it automatically becomes your **active** task. Subsequent tasks are added as **pending**.

- Your active task is what shows as your current focus in the overlay and in `!check` responses.
- When you complete a task with `!done`, the next pending task is automatically activated.
- Use `!focus <number>` to manually switch which task is active. The number is the position in your task list (1-based). The old focus stays **started** if you have room, otherwise it goes back to waiting.

## Started tasks (`!start` / `!pause`)

Besides your one focus, you can keep up to **2 more tasks started**: in progress, but parked. That is **3 going at once**.

- `!start 2` starts your task #2. If nothing is going yet, it becomes your focus (`Started "…", you. It's your focus now.`); otherwise the bot says how many you have going (`Started "…", you. 2/3 in progress.`).
- With 3 already going, `!start` refuses and changes nothing: `you already have 3 going. Finish one with !done or pause one with !pause.` The limit is checked inside the database write, so two bot pages or two quick messages can never get past it.
- `!start` only takes a waiting task; on your focus, a started task or a number you don't have it says `Nothing to start there`.
- `!pause` with no number pauses your focus, like `!done` with no number finishes it. Your oldest started task takes over (or the first waiting one). `!pause 2` pauses task #2 if it's your focus or a started task; anything else gets `Nothing to pause`. A paused task goes back to waiting and keeps its number.
- `!check` adds `(+n more started)` when you have started tasks, for example `you're on "write intro" (+1 more started).` This note is built in and works with a reworded **Task Check** reply.
- When your focus is done, removed or paused, your oldest started task takes over before any waiting one.

## Today's plan

`!today` shows your active task first, followed by the next two tasks in your list, each with its number (`Now: #2 … · Next: #1 …`). Those are the numbers `!done`, `!edit`, `!remove`, `!focus`, `!start` and `!pause` take. Started tasks are listed right after your focus, as `Next`. If you have more open tasks, it shows how many remain. It only shows your own tasks; it does not assign due dates or expose another viewer's list.

## Command aliases

Broadcasters can remap command names in **Bot settings → Commands** (`/dashboard/bot/commands`). For example, you could set `add` to map to `task`, so viewers can use `!add` instead of `!task`.

An alias can point at any task or timer command (`task`, `done`, `edit`, `remove`, `focus`, `start`, `pause`, `check`, `today`, `next`, `help`, `clear`, `timer`) — not the meta or moderation commands (`!dw`, `!dwhelp`, `!dwcommands`, `!mute`, `!unmute`, `!block`, `!unblock`). Each alias and target is a single command name with no arguments, so `!ts` → `!timer start` is not supported. Aliases can't reuse a built-in command name, so the built-in commands always keep working regardless of your aliases.

To save requests on Cloudflare's free plan, the bot page only forwards chat lines that start with a DireWork command or one of your aliases; other bots' commands (`!lurk`, `!so`) never leave the page. An open bot page picks up **new aliases** within an hour; reload the bot page (or refresh the OBS browser source) to use them right away.

## Task priority

Tasks created by the broadcaster (stream owner) are pinned to the top of the list. Viewer tasks appear below in the order they were added.

## Bot responses

All bot response messages are customizable from **Bot settings → Replies** (`/dashboard/bot/replies`). Task and timer command groups can be switched on or off individually on **Bot settings → Commands** (or the Overview).

### Timer bot responses

| Message | Default | Variables |
| --- | --- | --- |
| Not Running | `The timer isn't running. Start it first.` | none |
| Wrong Command | `Didn't catch that. Try !timer start, pause, resume, skip, reset, or eta.` | none |
| Timer Running | `The timer is already running.` | none |
| Command Success | `Done.` | none |
| Cycle Wrong | `Pick a cycle count from 1 to 99, like !timer start 4.` | none |
| ETA | `This phase ends in {phase} · the session ends in {time}` | `{phase}`, `{time}` |

<Callout type="info">
  The bot replies to `!timer` commands, but does not announce phase changes on
  its own. DireWork runs on Cloudflare Workers with no always-on process, so
  there is nothing to fire a message when a focus block ends — the overlay is
  what shows the current phase. Editable "focus started" / "break started" /
  "stream starting" / "timer finished" messages used to exist here but never
  sent anything, so they were removed.
</Callout>

### Message variables reference

| Variable | Description |
| --- | --- |
| `{user}` | The Twitch display name of the person who ran the command |
| `{user2}` | The Twitch display name of the target user (e.g., `!check @other`) |
| `{task}` | The task text content |
| `{oldTask}` | The task that was just completed (used in `!next`) |
| `{newTask}` | The new task now being tracked (used in `!next`) |
| `{count}` | How many tasks the viewer has going after `!start` (focus + started) |
| `{max}` | The most tasks one viewer can have going at once (3) |
| `{channel}` | The Twitch channel name, used as @mention to ping chat |
| `{phase}` | Time remaining in the current phase, as a relative duration (e.g., `18m`) |
| `{time}` | Time remaining until the whole session ends, as a relative duration (e.g., `1h 55m`) |
