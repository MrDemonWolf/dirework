DireWork ships a small design system so the web app, the docs site, and the OBS overlays all speak the same visual language. `design-system/tokens.json` is the source of truth: it generates the color, radius, type, motion, and layout CSS for both the app and the docs site, the landing-page theme gallery, and holds the squircle radius.

## Source of truth

```text
design-system/
  tokens.json          # the tokens — edit this
  scripts/render.ts    # pure renderers (tokens → CSS / TS strings)
  scripts/generate.ts  # writes the generated files
  README.md            # full reference
  components/          # one spec per component (README = index + page map)
```

Regenerate the outputs from the repo root:

```bash
bun run tokens
```

This writes three committed files:

| Output | Consumed by |
| --- | --- |
| `apps/web/src/tokens.generated.css` | The web app, imported by `apps/web/src/index.css` |
| `apps/fumadocs/src/app/tokens.generated.css` | The docs site, imported by `apps/fumadocs/src/app/global.css` |
| `apps/fumadocs/src/app/(home)/_widgets/overlay-themes.generated.ts` | Landing-page theme gallery |

Never edit a generated file by hand: change `tokens.json`, run `bun run tokens`, and commit both. CI checks for drift with `bun run tokens && git diff --exit-code`, and a web unit test (`design-tokens.test.ts`) fails if a committed CSS file doesn't match what `tokens.json` renders. A second test (`tokens-contrast.test.ts`) checks the palette's text pairs and status chips against WCAG AA (4.5:1) in both themes.

Shared overlay geometry and clock formatting (`roundedRectPath`, `roundedRectPerimeter`, `formatClock`, `SQUIRCLE_RADIUS`) live in the workspace package `@dirework/overlay-kit` (`packages/overlay-kit`), used by both the real OBS overlays and the docs mocks. A unit test in the web app keeps `tokens.json` in sync with the Theme Center presets and `SQUIRCLE_RADIUS`.

## Neutral dark

The visual language is a conventional **neutral dark UI**, the kind GitHub, Vercel and
Linear ship: near-black zinc surfaces with no color cast (background `#0c0c0e`, cards
`#151518`), off-white text (`#ededef`) and muted gray secondary text (`#a1a1aa`). Light
mode is fully supported (`#fafafa` page, white cards, the same blue). The console grammar
stays: panels, mono uppercase labels, LED-style status chips.

- **Accent blue, two forms:** `--primary` (`#236fea` dark / `#1866e0` light) is the fill
  behind white labels (primary buttons, avatar, checked states); `--link` (`#4f99f9` dark /
  `#155ed0` light) is the text form (links, icons, active nav, focus ring). No single blue
  clears 4.5:1 both under white text and as text on near-black, so text always uses `text-link`.
- **Secondary accent:** Cornflower (`--cornflower`).
- **Twitch:** `#9146FF` is reserved for "Sign in / Connect with Twitch" actions only.
- **Phase colors:** work = emerald `#34C759`, break = blue, long break = cornflower, paused = amber `#FF9F0A`.
- **State:** emerald = live / connected, amber = paused / warning (LED-style chips).

Type:

- **Display / headings:** Montserrat (`--font-display`)
- **Body:** IBM Plex Sans (`--font-body`)
- **Labels & numerals:** IBM Plex Mono (`--font-mono`) — timer digits use `tabular-nums`

## Tokens

Each generated stylesheet declares the palette as plain CSS variables on `:root` (light) and `.dark` (dark; the docs copy also follows the OS preference before a theme class is set) and registers them with Tailwind, so `bg-background`, `text-muted-foreground`, `bg-twitch`, `rounded-2xl`, `text-2xs`, `tracking-label` and friends all read the same values.

| Group in `tokens.json` | CSS variables | Notes |
| --- | --- | --- |
| `color.scheme.{light,dark}` | `--background`, `--primary`, `--success`, `--border`, `--hairline`, `--cornflower`, `--chart-*`, `--sidebar-*`… | The UI palette, as oklch values. `{name}` aliases another key (`--chart-2: var(--cornflower)`). |
| `color.phase` | `--phase-{work,break,long-break,paused}` | Timer phase accents |
| `color.console` | `--color-console-*` (`bg-console-base`…) | The always-dark bot page notices, app only |
| `color.partner` | `--twitch`, `--twitch-hover` (`bg-twitch`) | Twitch purple, for Twitch actions only |
| `radius` | `--radius` + `--radius-{xs…4xl}` | App only, as offsets from `--radius` (12px) |
| `font.size`, `font.lineHeight` | `--text-2xs`, `--text-3xs` | Steps Tailwind doesn't ship; the rest are Tailwind's defaults, listed for reference |
| `tracking` | `--tracking-{chip,label,eyebrow,display,marquee}` | Letter-spacing for chips, labels, display caps |
| `motion` | `--ease-console`, `--animate-console-rise(-fast)` | Plus the `console-rise` keyframes |
| `layout` | `--container-{content,editor}`, `--spacing-header` | Page widths and the sticky header height |
| `z` | `--z-{save-bar,header,skip-link}` | Stacking order |
| `color.brand`, `color.semantic`, `color.partner.{discord,obs}` | none | Hex palette for OG images and docs widgets |

The docs stylesheet (`apps/fumadocs/src/app/global.css`) maps the generated palette onto the names the docs surfaces read, and keeps a few docs-only values by hand:

| Namespace | Variable pattern | Example |
| --- | --- | --- |
| Fumadocs | `--color-fd-*` | `--color-fd-background: var(--background)` |
| Brand | `--brand-500` / `--brand-600` / `--brand-50` | `--brand-500: var(--primary)` (accent fill), `--brand-600: var(--link)` (accent text) |
| Phase | `--phase-{work,break,long-break,paused}` | timer ring + status accents |
| Partner | `--color-twitch`, `--color-live` | Twitch actions / live state |
| Surface | `--bg-base` / `--bg-surface` / `--bg-elev` | `var(--background)` / `var(--muted)` / `var(--card)` |
| Text | `--txt-1` / `--txt-2`, `--hairline` | `var(--foreground)` / `var(--muted-foreground)` |
| Fonts | `--font-display` / `--font-body` / `--font-mono` | Montserrat / Plex Sans / Plex Mono |
| Radius | `--dw-radius-control` | `9px` — pills, chips, kickers, buttons |

Fonts stay hand-written in both stylesheets because they wrap the `next/font` variables. The docs copy carries no radius scale: fumadocs-ui compiles its own `rounded-*` utilities against the docs theme, so overriding it would restyle every fumadocs component.

## The `dw-*` utility layer

The marketing and docs surfaces use a thin set of utility classes (defined in
`apps/fumadocs/src/app/global.css`) that read the tokens. They keep the landing page
token-backed without pulling in a component framework.

| Class | Purpose |
| --- | --- |
| `dw-display` / `dw-mono` | Montserrat heading + Plex Mono label styles |
| `dw-text-1` / `dw-text-2` / `dw-text-brand` | Text hierarchy |
| `dw-bg-base` / `dw-bg-surface` / `dw-bg-elev` | Surfaces |
| `panel` / `panel-hero` / `panel-inset` | Flat instrument panels (workhorse / gradient hero / recessed well) |
| `console-label` / `console-rule` | Mono section label + labeled hairline rule |
| `dw-chip` + `dw-chip-{accent,live,warn}` | LED-style status chips |
| `dw-kicker` + `dw-kicker-num` | Numbered section kicker (`01 · …`) |
| `dw-card` / `dw-card-hover` | Content container |
| `dw-btn` + `dw-btn-{primary,secondary,twitch,ghost}` | Buttons |
| `dw-pill` | Metadata / trust chip |
| `dw-code` | Code well |
| `bg-grain` / `bg-checker` | Module grain / OBS transparency preview |
| `preview-scene-dark` / `-light` / `-bright` | Theme Center preview backdrops (simulated stream scenes) |
| `dw-reveal-{1,2,3}` / `animate-led-pulse` | Staggered entrance + LED pulse |

## Component catalog

Every component has one spec under `design-system/components/`: each module in
`apps/web/src/components/` (the `ui/` primitives, the shared components, and the
`theme-center/`, `bot-settings/` and `icons/` folders), plus every docs landing widget (the `.tsx` files in `apps/fumadocs/src/app/(home)/_widgets/`). A
spec opens with `source:` (the file it documents) and `tokens:` (the `tokens.json` families
it reads) frontmatter, then Purpose, Anatomy, Props and variants, States, Accessibility
(including the roles and names the e2e tests pin), and Do / Don't. The catalog's
`README.md` maps each page to the components it renders.

`apps/web/src/lib/__tests__/spec-catalog.test.ts` keeps the catalog honest: every `source:`
must exist, every component file must be claimed by exactly one spec, every spec must have a
row below whose Source matches its `source:`, sit in one README catalog group and in the
README page map, and the "Pinned values" tables in `timer-ring.md` and `task-card.md` must
quote every leaf of `DEFAULT_TIMER_STYLES` / `DEFAULT_TASK_STYLES` and every
`lib/overlay-view.ts` constant. Renaming a component or changing or adding an overlay
default fails CI until its spec moves with it.

## Overlay themes

`overlay.themes` in `tokens.json` mirrors the 6 presets in `apps/web/src/lib/theme-presets.ts`, holding the four swatch colors each exposes (`bg`, `accent`, `text`, `username`). That data is generated into a typed module the landing-page gallery renders. When a preset's preview colors change, update `tokens.json` and run `bun run tokens`.

## Accessibility rules

- **Two themes, always.** Every surface must read in light and dark.
- **Never color alone.** Done tasks use strike-through *and* a dimmed color.
- **Honor reduced motion.** Animated primitives stop under `prefers-reduced-motion: reduce`.
- **Real interactive elements.** Buttons and links are `<button>`/`<a>`, never clickable `<div>`s.
